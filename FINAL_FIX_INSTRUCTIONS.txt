PROBLEM FIXED:
The system was detecting "orderID 2" in the query, but still performing a SUM 
operation instead of returning the specific row's value.

ROOT CAUSE:
The code was checking for "total" keyword AFTER the ID detection, so it would 
route to the SUM operation even when asking for a specific row.

SOLUTION:
1. Moved specific row detection BEFORE operation routing
2. Added early return for VALUE LOOKUP when only 1 record is filtered
3. Added support for typos like "oederID" instead of "orderID"
